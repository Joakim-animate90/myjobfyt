**MJF-046**

## Problem

Authenticated boards can only be reached legitimately through the candidate's own session, and the server must never hold their job-board credentials.

## Business impact

This is the boundary between legitimate assistance and account compromise. Crossing it would expose candidates to losing their LinkedIn or Indeed accounts.

## Technical impact

A queue endpoint returning extension-eligible applications with prepared field values, authenticated with a short-lived extension-audience token and a strict origin allowlist.

## Proposed solution

Implement the extension API surface behind the extension audience, which is already rejected against the main API. The server never receives credentials or session cookies. If a CAPTCHA or any anti-bot challenge appears, control is handed to the candidate; nothing is solved or bypassed.

## Acceptance criteria

- [ ] Extension tokens are short-lived and rejected against the main API
- [ ] No endpoint accepts a job-board credential or session cookie
- [ ] The origin allowlist is enforced
- [ ] Results report back and append application events
- [ ] No CAPTCHA or anti-bot handling exists anywhere in the codebase

## Testing requirements

Audience-isolation tests. A grep-based test asserting no credential-relay fields exist in any extension request type.
