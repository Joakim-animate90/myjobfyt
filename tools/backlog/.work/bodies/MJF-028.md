**MJF-028**

## Problem

Loops are the product's central abstraction and nothing implements them.

## Business impact

Without loops there is no automated search. Pause is the specific defect we identified in LoopCV and must not reproduce.

## Technical impact

Four-step resumable wizard, draft persistence, the draft/active/paused/archived state machine, config versioning, and a Redis kill-flag so pause takes effect in under a second.

## Proposed solution

Implement the loops domain. Pause sets a Redis flag that submission workers check immediately before every send, so pausing is near-instant rather than effective at the next scheduler tick. Every config change bumps config_version and snapshots the config, so a historical match can be explained by the settings in force when it was created.

## Acceptance criteria

- [ ] The wizard is resumable; a partial loop persists as draft
- [ ] Pause halts discovery and pending submissions within one second
- [ ] Editing an active loop takes effect from the next run and is recorded as a config version
- [ ] Duplicating copies configuration but no history
- [ ] Preconditions are enforced at the step where they apply, not at submit
- [ ] The active_loops entitlement is enforced

## Testing requirements

State-machine tests for every transition including illegal ones. A race test pausing a loop while a submission is in flight, asserting the pre-send gate catches it.
