**MJF-034**

## Problem

A candidate who loosens a filter should not wait a day to see the effect.

## Business impact

The filter-tuning journey is how a candidate recovers from a too-narrow search. A day's delay makes it unusable.

## Technical impact

Republish matching.requested for recent postings when a loop's config_version or cv_version changes.

## Proposed solution

Implement a backfill planner triggered by config and CV changes, bounded to the last N days, with the idempotency key including config_version so unchanged pairs are not rescored.

## Acceptance criteria

- [ ] A filter change rescores recent postings within minutes
- [ ] A new CV version rescores the loop's matches
- [ ] Unchanged pairs are not rescored
- [ ] Backfill cannot starve live matching

## Testing requirements

Integration test: tighten then loosen a filter, assert match counts change appropriately and no duplicate matches appear.
