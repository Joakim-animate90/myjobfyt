**MJF-020**

## Problem

There is no abstraction over job sources. Without one, each integration would hand-roll its own rate limiting and failure handling and a single bad source could stall all discovery.

## Business impact

Job supply is the product's raw material. One failing board must not stop the others.

## Technical impact

The Adapter interface from docs/INTEGRATION_ANALYSIS.md, a registry, per-source rate limiting enforced inside the adapter, a persisted circuit breaker, and capability declaration.

## Proposed solution

Implement internal/domain/jobs/adapter with the documented interface. Capabilities drive planner behaviour so an unsupported query is skipped rather than issued and failed. Breaker state persists on job_sources so a restart does not immediately hammer a failing source.

## Acceptance criteria

- [ ] Every adapter implements Slug, Capabilities, Search, Fetch and HealthCheck
- [ ] Rate limiting is enforced inside the adapter so a scheduling bug cannot cause abuse
- [ ] A failing source degrades a run and never fails it
- [ ] Repeated failure opens the breaker, alerts, and persists across restart
- [ ] A source cannot be enabled without a recorded legal_basis

## Testing requirements

A shared conformance suite every adapter must pass. Breaker tests for open, half-open and close transitions.
