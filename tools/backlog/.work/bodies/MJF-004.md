**MJF-004**

## Problem

Every AI feature needs a shared client. Without one, each feature would reimplement schema validation, retries, timeouts and cost tracking, and they would diverge.

## Business impact

AI is the product's core differentiator and its largest variable cost. Untracked spend is an unbounded liability.

## Technical impact

Needs a provider interface, schema-constrained generation, bounded retries with a repair prompt on schema violation, per-call timeouts, output token caps, token accounting per purpose, and a prompt-injection-safe message construction helper.

## Proposed solution

Implement internal/platform/ai with a Provider interface, an Anthropic implementation defaulting to the current Claude models, and a Generate[T] helper that validates against a JSON schema and retries at most twice with a repair prompt. Untrusted text is passed only through a delimited data block helper that cannot be bypassed.

## Acceptance criteria

- [ ] No domain package imports a provider SDK directly
- [ ] A schema violation retries twice with a repair prompt, then returns a terminal error
- [ ] prompt_tokens, completion_tokens and total_tokens are recorded per call, labelled by purpose
- [ ] The ai_tokens_month quota is enforced before the call
- [ ] Prompt and completion bodies are never logged
- [ ] Untrusted text can only be included via the delimited-data helper

## Testing requirements

Unit tests with a fake provider: valid response, schema violation then recovery, schema violation exhausted, timeout, rate limit. A test asserting an injection string inside the data block does not alter the instruction portion.
