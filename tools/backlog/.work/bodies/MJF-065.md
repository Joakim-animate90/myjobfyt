**MJF-065**

## Problem

Entitlements are defined in the plans table but nothing enforces them, and there is no billing integration.

## Business impact

No revenue, and no protection against a single user consuming unbounded AI spend.

## Technical impact

Stripe checkout, signature-verified idempotent webhooks as the source of truth, entitlement resolution, Redis quota counters with a nightly Postgres reconciliation, and graceful degradation at the limit.

## Proposed solution

Implement entitlements.Check as the single enforcement point. Webhooks are keyed on the provider's event id because providers deliver duplicates and out-of-order events routinely. Exceeding a quota degrades gracefully: matches keep accumulating and submissions queue rather than fail.

## Acceptance criteria

- [ ] Quotas are enforced server-side only; a client-supplied tier is never trusted
- [ ] Webhook signatures are verified and processing is idempotent on the provider event id
- [ ] Out-of-order webhooks do not corrupt subscription state
- [ ] A lost webhook is caught by nightly reconciliation
- [ ] Exceeding a quota queues submissions rather than losing them
- [ ] A Redis outage falls back to the Postgres rollup with a conservative cap

## Testing requirements

Webhook replay, duplicate and out-of-order tests. Quota boundary tests. A Redis-failure test asserting the conservative fallback.
