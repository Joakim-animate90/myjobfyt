**MJF-082**

## Problem

No test covers a complete candidate journey, so an integration gap between working components would go unnoticed.

## Business impact

Components can each pass their tests while the journey is broken.

## Technical impact

Playwright against a real stack, covering register through to analytics.

## Proposed solution

Implement the journeys from docs/USER_JOURNEYS.md: register, onboard, upload a CV, parse it, configure a loop, discover from a fixture source, match, tailor, prepare, authorise, submit, update status and view analytics.

## Acceptance criteria

- [ ] The full primary journey passes against a real stack
- [ ] The diagnose-no-matches journey passes
- [ ] Accessibility assertions run on every screen visited
- [ ] The suite is stable enough to gate merges, with no flaky retries masking failures

## Testing requirements

Run 20 consecutive times and require zero flakes before enabling as a gate.
