**MJF-010**

## Problem

Candidates need several CVs and version history, and a CV referenced by a submitted application must never disappear.

## Business impact

Multiple CVs enable the A/B testing feature. Losing the CV behind a submitted application destroys the audit trail.

## Technical impact

List, rename, set-default, soft-delete endpoints; version chain; RESTRICT on the application foreign key is already in the schema.

## Proposed solution

Implement the CRUD endpoints with user_id scoping. Soft-delete only; refuse hard deletion of a version referenced by any application and explain why.

## Acceptance criteria

- [ ] A candidate sees only their own CVs
- [ ] At most one default CV per candidate, enforced by the existing partial unique index
- [ ] A version used by a submitted application cannot be deleted
- [ ] Version history is preserved and browsable

## Testing requirements

Tenant-isolation test asserting another user's CVs are invisible and unmodifiable. A test proving a referenced version resists deletion.
