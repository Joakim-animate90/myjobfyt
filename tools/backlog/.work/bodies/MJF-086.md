**MJF-086**

## Problem

There is no API specification, so clients have nothing to generate from and no contract to rely on.

## Business impact

The frontend and the extension both need a reliable contract.

## Technical impact

An OpenAPI 3.1 document covering every endpoint, request and response, verified against the running API so it cannot drift.

## Proposed solution

Write the specification and add a contract test that exercises it against the live API, so a divergence fails CI. A specification nobody verifies is worse than none, because it is believed.

## Acceptance criteria

- [ ] Every endpoint, request schema and response schema is documented
- [ ] Error responses and their codes are documented
- [ ] A contract test verifies the specification against the running API in CI
- [ ] A client generated from the specification works against the real API

## Testing requirements

The contract test is the verification. It must fail when an endpoint changes without the specification being updated.
