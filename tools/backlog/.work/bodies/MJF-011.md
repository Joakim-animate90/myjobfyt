**MJF-011**

## Problem

Tailoring is the highest-value AI feature and the highest-risk: an LLM asked to improve a CV for a job will invent experience unless actively prevented.

## Business impact

A fabricated line on a CV is a lie told in the candidate's name to an employer. It can cost them the role and their reputation. This is the product's most serious safety requirement.

## Technical impact

Generate a tailored version constrained to the parsed CV as the sole factual source, then run a post-generation validator that diffs against the source and rejects any new employer, title, date, certification or skill.

## Proposed solution

Implement the containment validator as a hard gate, independent of the prompt. Prompt compliance is necessary but insufficient, and a job description can carry an injection requesting exactly the fabrication we forbid. On rejection, retry once with a stricter prompt, then report that tailoring could not be completed safely. Persist containment_passed; the schema already requires it to be non-null for a tailored version.

## Acceptance criteria

- [ ] Output introducing any employer, title, date, certification or skill absent from the source is rejected
- [ ] Unvalidated output is never surfaced to the candidate or attached to an application
- [ ] The candidate sees a diff against the source before the tailored CV is used
- [ ] containment_passed is recorded on every tailored version
- [ ] A prompt-injection attempt in the job description cannot defeat the validator

## Testing requirements

Adversarial suite: job descriptions demanding skills the candidate lacks; descriptions containing explicit injection instructions; a mocked provider returning fabricated content, asserting rejection. This suite is a release gate.
