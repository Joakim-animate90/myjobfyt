**MJF-071**

## Problem

There is no Kubernetes deployment definition.

## Business impact

Blocks deployment to the VPS cluster and any later migration to managed Kubernetes.

## Technical impact

Deployments for api, worker (per group) and scheduler; services; ingress; configmaps; secret references; probes; resource requests and limits; HPA; network policies; pod security contexts; and a migration job with correct ordering.

## Proposed solution

One chart with three value files. Worker deployments are split by consumer group so an AI outage stalls cv consumers while applications keeps submitting. The migration job is a pre-install and pre-upgrade hook so the schema is always ahead of the code.

## Acceptance criteria

- [ ] One chart deploys to all three environments via values alone
- [ ] Workers are separately scalable per consumer group
- [ ] Liveness, readiness and startup probes are wired to the real endpoints
- [ ] Resource requests and limits are set on every container
- [ ] Network policies default to deny
- [ ] Pod security contexts drop all capabilities and disallow privilege escalation
- [ ] The migration job runs before the application starts
- [ ] helm lint and a template render pass for all three environments

## Testing requirements

helm lint, helm template, and kubeconform validation in CI. A deploy to a local kind or k3s cluster as an integration gate.
