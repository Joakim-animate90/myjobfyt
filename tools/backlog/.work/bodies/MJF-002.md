**MJF-002**

## Problem

No endpoint exists to accept a CV. The schema is ready but nothing writes to it.

## Business impact

Step 4 of the primary onboarding journey. A candidate cannot proceed without it.

## Technical impact

Multipart upload, a transaction creating the document and its first version, publishing cv.uploaded, and returning immediately with a parsing status so the client can poll.

## Proposed solution

POST /v1/cvs accepting multipart, streamed through the storage layer. Create cv_documents plus cv_versions(version_no=1) in one transaction, then publish cv.uploaded after commit. Enforce the cv_slots quota before accepting the body.

## Acceptance criteria

- [ ] Upload returns 202 with a document id and parse_status=pending
- [ ] The cv_slots entitlement is checked before the body is read, not after the file is stored
- [ ] cv.uploaded carries cv_id, version_id, user_id, storage_key, content_type, size and checksum
- [ ] A storage failure leaves no database row
- [ ] Re-uploading the same file content creates a new version, not a duplicate document

## Testing requirements

API tests for success, oversized, wrong type, quota exceeded and storage-unavailable. Verify no orphaned rows after an induced storage failure.
