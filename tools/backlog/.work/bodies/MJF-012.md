**MJF-012**

## Problem

Candidates need to create or restructure a CV in the product, and rendering user content to PDF is an SSRF and local-file-inclusion risk.

## Business impact

Removes the dependency on external CV tools and makes ATS-parseable output the default.

## Technical impact

Template registry, server-side HTML-to-PDF rendering, a preview that uses the same renderer as the final output.

## Proposed solution

Render in a sandboxed container with no network egress and no filesystem access beyond bundled fonts. Allowlist templates strictly. Use one renderer for both preview and output so what is previewed is what is produced.

## Acceptance criteria

- [ ] Output is real text, single column by default, and ATS-parseable
- [ ] The renderer has no network access and cannot read local files
- [ ] Only allowlisted templates can be rendered
- [ ] Preview and final PDF are byte-identical for the same input
- [ ] A renderer timeout returns a clear failure, never a corrupt PDF

## Testing requirements

SSRF attempt tests (remote image, remote CSS, file:// reference) asserting each is blocked. A determinism test. An ATS-parseability check extracting text back out of the generated PDF.
