**MJF-061**

## Problem

Sending application emails without suppression and bounce handling destroys deliverability for every candidate on the platform.

## Business impact

One candidate's spam complaints must not poison delivery for everyone else.

## Technical impact

Platform sending with the candidate in Reply-To, optional candidate SMTP with envelope-encrypted credentials, per-recipient-domain rate limits, global suppression checked before every send, and bounce and complaint handling.

## Proposed solution

Implement the send path with the suppression check as an unconditional pre-send gate. SMTP credentials are write-only through the API, never returned and never logged. Hard bounces suppress permanently; complaints suppress and alert.

## Acceptance criteria

- [ ] The suppression list is checked before every send without exception
- [ ] SMTP credentials are never returned by any endpoint and never appear in logs
- [ ] Per-recipient-domain rate limits are enforced
- [ ] A hard bounce suppresses permanently; a complaint suppresses and alerts
- [ ] An SMTP auth failure disables the config and notifies the candidate

## Testing requirements

A test asserting no send path bypasses the suppression check. Credential-exposure tests across every endpoint and log line.
