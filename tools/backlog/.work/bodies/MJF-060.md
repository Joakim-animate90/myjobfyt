**MJF-060**

## Problem

The email application channel needs recruiter addresses, and obtaining them unlawfully would be both illegal and reputationally fatal.

## Business impact

Email is a real application channel, but a GDPR violation or a spam reputation would end the product.

## Technical impact

Contacts only from the posting itself, the company's published careers address, or a licensed provider. Every contact records provenance, lawful basis and verification state.

## Proposed solution

Implement discovery from lawful sources only. No email-pattern guessing — the contact_provenance enum has no value for it, so it is structurally impossible. Unverified addresses are never used for automated sending.

## Acceptance criteria

- [ ] Every contact records provenance and a lawful basis
- [ ] No code path constructs an address from a name-and-domain pattern
- [ ] Unverified addresses are excluded from automated sending
- [ ] Provenance is auditable per contact

## Testing requirements

A test asserting no pattern-guessing code path exists. Provenance-recording tests per source.
