**MJF-085**

## Problem

Nothing establishes the platform's capacity or its behaviour under dependency failure.

## Business impact

Capacity limits discovered in production are discovered by candidates.

## Technical impact

Load tests for the API and the pipeline, concurrency tests on the authorisation and quota paths, and failure-recovery tests for each dependency.

## Proposed solution

Build load profiles for the API and for discovery-through-matching. Concurrency tests target the paths where a race would be serious: quota reservation and application authorisation. Failure tests kill each dependency in turn and assert the documented degradation.

## Acceptance criteria

- [ ] API p99 latency stays within target at the documented concurrency
- [ ] Matching throughput is measured and documented
- [ ] No double submission occurs under concurrent authorisation attempts
- [ ] No quota over-consumption occurs under concurrent requests
- [ ] Each dependency failure produces the documented degradation, not an outage
- [ ] Workers resume correctly after a restart mid-pipeline
- [ ] Event replay is verified

## Testing requirements

This issue is the testing. Results are recorded in docs as the capacity baseline.
