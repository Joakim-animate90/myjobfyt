**MJF-007**

## Problem

The parse pipeline described in docs/SYSTEM_WORKFLOWS.md W1 has no consumers. Uploaded CVs would stay in pending forever.

## Business impact

A CV that never parses is a candidate who cannot use the product, with no explanation.

## Technical impact

Chained consumers: av-scan, text-extract, structure, skill-normalise, embed. Each idempotent, with the documented AckWait, MaxDeliver and timeouts.

## Proposed solution

Register the consumers in internal/worker under the cv group. Idempotency key cv.parse:{cv_version_id}. InFlightRetry throughout, since re-parsing is harmless. Publish cv.parsed on success and cv.parse_failed with the stage on terminal failure.

## Acceptance criteria

- [ ] All five stages run in order and are individually idempotent
- [ ] A redelivery after a crash does not duplicate derived rows
- [ ] A terminal failure dead-letters with the stage recorded and notifies the candidate
- [ ] Dead-letter depth above zero raises an alert
- [ ] The whole chain appears as one OpenTelemetry trace

## Testing requirements

Integration test against real Postgres, NATS and MinIO: upload to parsed, crash-and-resume mid-pipeline, and a poison message reaching the dead-letter queue.
