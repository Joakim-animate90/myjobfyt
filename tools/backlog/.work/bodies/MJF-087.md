**MJF-087**

## Problem

The security decisions are embedded in code comments and commit messages rather than stated anywhere a reviewer can read them.

## Business impact

Required for any serious customer conversation, and for the team to reason about risk consistently.

## Technical impact

A threat model, a security overview, and a release checklist.

## Proposed solution

Document the eight security boundaries from docs/ARCHITECTURE.md as a threat model with assets, actors, threats and controls. SECURITY.md covers reporting and the supported versions. The checklist is a release gate.

## Acceptance criteria

- [ ] The threat model covers every boundary with assets, threats and controls
- [ ] The upload, prompt-injection, tenant, submission, credential and secret boundaries are each documented
- [ ] The common-password list's limitations are stated, with the recommended production approach
- [ ] SECURITY.md states how to report a vulnerability
- [ ] The checklist is used as a release gate, not written and forgotten

## Testing requirements

Review against the invariant-auditor agent's findings; any gap it reports that the documents do not cover is a defect in the documents.
