**MJF-081**

## Problem

Repository SQL, worker pipelines and the database invariants are only verified by hand. A regression in any of them would reach production.

## Business impact

The invariants protecting candidates from unauthorised submissions and fabricated CVs must be continuously verified, not verified once.

## Technical impact

Testcontainers for Postgres, Redis, NATS and MinIO, behind the integration build tag, covering repositories, migrations, workers, event processing and the database constraints.

## Proposed solution

Build the harness and port the manual verifications already performed into permanent tests: every database invariant attempting its violation, the full CV parse pipeline, discovery through matching, and the authorisation gate.

## Acceptance criteria

- [ ] Every repository method is covered against real Postgres
- [ ] Every database CHECK and trigger has a test attempting to violate it
- [ ] Migrations are tested up, down and up again with no residue
- [ ] Worker pipelines are tested including crash-and-resume and dead-lettering
- [ ] Tenant isolation is asserted per repository
- [ ] The suite runs in CI on every pull request

## Testing requirements

This issue is the testing. Each invariant test must be seen to fail when its constraint is removed.
