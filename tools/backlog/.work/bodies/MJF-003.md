**MJF-003**

## Problem

A CV must be converted to text before anything can parse it. Sending a PDF straight to an LLM wastes tokens and loses layout information we can extract reliably and for free.

## Business impact

Parse quality determines match quality, which determines whether the product works at all.

## Technical impact

PDF text extraction plus DOCX XML extraction, with page and character counts. Must detect the image-only PDF case explicitly.

## Proposed solution

Implement extraction in the cv worker. For PDF use a pure-Go extractor; for DOCX read word/document.xml. Record char_count and page_count on the version. If char_count is zero, emit cv.parse_failed with reason=no_extractable_text and a clear candidate-facing message.

## Acceptance criteria

- [ ] Text, page count and character count are persisted on the cv_version
- [ ] A scanned image-only PDF produces an explicit, actionable failure rather than an empty profile
- [ ] An encrypted or password-protected PDF is rejected with a clear message
- [ ] Extraction completes within 30 seconds for a 10-page CV
- [ ] CV text never appears in any log line

## Testing requirements

Fixture corpus: text PDF, scanned PDF, encrypted PDF, DOCX, DOCX with tables, malformed file, 50-page document. Assert the failure reason for each bad case.
