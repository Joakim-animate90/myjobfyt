**MJF-032**

## Problem

Scoring every new posting against every active loop is quadratic and will not scale past a few thousand candidates.

## Business impact

Determines how many candidates the platform can serve per unit of compute.

## Technical impact

An inverted index over title tokens, geo keys and work mode to prefilter candidate loops before scoring.

## Proposed solution

Implement match-fanout with a prefilter, then score only plausible pairs. Measure the reduction and alert if the prefilter stops being effective.

## Acceptance criteria

- [ ] A new posting fans out only to loops that could plausibly admit it
- [ ] The prefilter never excludes a pair that full scoring would have matched
- [ ] Matching lag stays within target at 10k active loops
- [ ] Prefilter effectiveness is a published metric

## Testing requirements

A correctness test asserting the prefilter is a superset of true matches. A load test at 10k loops and 50k postings.
