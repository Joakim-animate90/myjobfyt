**MJF-031**

## Problem

Matching is the product's core intelligence, and an unexplainable score is a support ticket. LoopCV's opaque Low/Middle/High knob is the defect we are replacing.

## Business impact

Candidates act on these scores. If they cannot see why a job scored 82, they cannot trust or tune the system.

## Technical impact

Independent dimension scores — title similarity, required and nice-to-have skill overlap, years of experience, seniority fit, location fit, employment type fit — combined with versioned weights, producing per-dimension sub-scores and human-readable reasons.

## Proposed solution

Implement scoring with each dimension independently testable. Build the reason text from the structured sub-scores rather than from free-form LLM output, so an explanation cannot leak prompt content. Weights live in versioned config so historical scores stay interpretable.

## Acceptance criteria

- [ ] Every match carries per-dimension sub-scores and reasons
- [ ] The numeric threshold plus the low/middle/high presets both work and agree
- [ ] Weights are versioned; config_version is recorded on each match
- [ ] Scoring is deterministic for identical inputs
- [ ] Explanation text is generated from structured data, never raw model output
- [ ] Degraded scoring is marked and rescored later, never dropped

## Testing requirements

Per-dimension unit tests. A golden-set regression suite of CV/posting pairs with expected score ranges, acting as a guard against scoring drift.
