**MJF-075**

## Problem

Infrastructure is provisioned by hand, so it is undocumented and unreproducible.

## Business impact

A lost server would be a manual, error-prone rebuild.

## Technical impact

Modules for the VPS, DNS records, S3-compatible storage buckets with lifecycle rules, and backup storage, with remote state.

## Proposed solution

Write modules with remote state and locking. Keep the module boundaries aligned with the migration path to managed Kubernetes, so moving Postgres to a managed instance is a variable change rather than a rewrite.

## Acceptance criteria

- [ ] terraform plan is clean against live infrastructure
- [ ] State is remote and locked
- [ ] Buckets have lifecycle and retention rules
- [ ] No credential is committed
- [ ] The managed-Kubernetes migration path is documented

## Testing requirements

terraform validate and plan in CI. A full apply into a scratch project.
