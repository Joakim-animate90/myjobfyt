**MJF-006**

## Problem

Raw skill strings are not comparable. 'JS', 'Javascript' and 'JavaScript' would be treated as three unrelated skills, making skill-overlap scoring meaningless.

## Business impact

Skill overlap is one of the heaviest match dimensions. If it is noise, matching is noise.

## Technical impact

Map extracted labels onto the skills table via canonical name, aliases and trigram similarity, persisting cv_skills with the raw label retained.

## Proposed solution

Seed the taxonomy with a substantial skill set and alias list. Normalise by exact match, then alias, then trigram similarity above a threshold. Retain the raw label so nothing is lost, and leave skill_id null rather than forcing a bad match.

## Acceptance criteria

- [ ] Common aliases resolve to one canonical skill
- [ ] An unrecognised skill is retained with a null skill_id rather than force-matched
- [ ] The raw label is always preserved
- [ ] Normalisation is deterministic for a given input

## Testing requirements

A table test of alias resolution, including near-misses that must NOT match (e.g. 'Java' must not resolve to 'JavaScript').
