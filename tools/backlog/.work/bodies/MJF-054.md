**MJF-054**

## Problem

Matches are the product's output and there is nowhere to see them.

## Business impact

This is the screen a candidate opens every day. It is the product.

## Technical impact

A virtualised, server-paginated, filterable match list; a detail view with the full score breakdown; the rejected-matches browser filtered by category; and bulk actions.

## Proposed solution

Build the list with saved filters and keyboard navigation, the detail view showing every sub-score and reason, and the rejected browser that turns 'why no matches?' into self-service. Empty states name the current pipeline stage.

## Acceptance criteria

- [ ] The list is server-paginated and stays responsive at thousands of matches
- [ ] The detail view shows every dimension's sub-score and reason
- [ ] Rejected matches are browsable by category and can still be applied to
- [ ] Bulk actions are optimistic and roll back on failure
- [ ] The empty state names the pipeline stage and expected timing, never a bare spinner

## Testing requirements

Virtualisation performance test at 5000 rows. A test asserting the empty state renders stage information.
