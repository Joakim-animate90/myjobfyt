**MJF-041**

## Problem

What gets sent must be known and fixed before authorisation, or the audit trail is decorative and consent is meaningless.

## Business impact

The candidate is consenting to specific content. If the content can change after consent, the consent is worthless.

## Technical impact

Resolve the CV version, render the cover letter and email body from the template, map form fields from the profile, collect unknown screening questions, and persist all artefacts immutably.

## Proposed solution

Implement preparation writing every artefact to the application row. The applications_freeze_authorised_artefacts trigger already makes them immutable post-authorisation. A missing required field moves the application to blocked with a precise reason and a deep link to fix it, rather than failing at submit time.

## Acceptance criteria

- [ ] All artefacts are persisted and are byte-identical to what will be sent
- [ ] Template rendering uses only the allowlisted placeholders; an unknown placeholder is a validation error
- [ ] A missing required field blocks with an actionable reason
- [ ] Preparation never sends anything
- [ ] Artefacts cannot be modified after authorisation

## Testing requirements

Tests asserting artefact immutability post-authorisation, template placeholder validation, and the blocked path for each required field.
